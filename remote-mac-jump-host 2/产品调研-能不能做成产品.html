手机 → 公网跳板 → 家里 Mac → 驱动 AI Agent
这套手搓方案，能不能做成产品？

主市场：中国 · 唯一要回答的问题：这是不是一个值得做的好产品。源料：moshi-config 仓库（教程 + 脚本）

结论 · 不做

作为独立付费产品 —— 不做。
它是一份好内容、一个好个人品牌资产，但不是一个好产品。

你以为的「独有内核」（国内跳板绕开被墙中继），既有现成原生替代（自建 DERP），又刚被平台亲手掀掉地基（Anthropic 官方 Remote Control）。痛点根因被误诊，中国楔子 TAM 仅几千到两三万人，且付费意愿被免费生态双重稀释。最靠谱的"形态"不是产品，是把它当内容 / 影响力资产继续做。

一先把"这"是什么说清楚

产品判断必须建在正确的对象上。

你这套栈里，"手机终端 App + agent 完成/审批推送"这一层已经是一个在卖的成品 —— Moshi（getmoshi.app），你的仓库本身叫 moshi-config、写明"与 getmoshi.app 无隶属关系"，它是架在 Moshi 之上的配置 + 教程。语音输入、moshi-hook 推送、tmux 集成、Diff Viewer 都是 Moshi 的产品功能。

所以你真正独有的内核，比"整套栈"窄得多，只有两块：① 国内跳板方案（绕开被墙 DERP）+ ② 把一堆手动坑固化成"一键打通"的打包。下面四条，正是冲着这两块去验证的。

二独有内核①：国内跳板，有现成原生解，没有独特价值

前置技术核查 —— 这一条本身就能左右结论。

自建 DERP 已是国内 Tailscale 用户的事实标准

国内绕开被墙官方中继，主流解法不是 SSH 跳板，而是自建 DERP 节点。社区已演化出纯 IP + 自签证书 + Docker、无需域名、无需备案的姿势（ip_derper），中文教程满地（知乎/博客园/腾讯云/飞牛 NAS wiki），属常识级操作。headscale + 自建 derper 也是"全自建"用户的标配。

这里要说准一句，否则第六节自相矛盾：技术新颖度 = 零（自建 DERP 已原生解决）；但对"会命令行、非网络专家"的人，打包/省事是有真实价值的 —— "在一台我本来就有的 VPS 上配个 SSH 跳板"，确实比"部署并维护一个 derper 容器 + 自签证书 + 改 ACL derpMap + 绕备案"省心。只是这点价值商业上很薄。这个区分，正是第六节为什么"懒人包"只能当副线、不能当产品的根。

来源：Tailscale 官方 DERP 文档 · V2EX 国内搭建难点 · 飞牛 NAS wiki

三独有内核②：刚被平台亲手掀掉地基

这是最致命的一条。

Anthropic 官方 Remote Control（2026-02-25 上线）

本地 Claude Code 进程主动向 Anthropic 发出站 HTTPS，不在本机开监听端口，手机/网页当遥控器。全程不需要 Tailscale、不需要公网 IP、不需要内网穿透、不需要跳板。断网自动重连。Pro/Max 直接可用。

诚实边界（也是为什么它致命）：RC 目前只管 Claude Code、且是 research preview —— 它不覆盖 Codex/Gemini/Cursor/Kimi 等其它 agent，也不覆盖"连回家拿个文件、跑段脚本"这种通用远程。所以它没掀掉整个连接层，但它掀掉了最值钱的那一格 —— Claude Code 正是这套方案商业上唯一站得住的核心场景。官方用一条出站 HTTPS（国内访问 Anthropic 本来就走这条、根本不碰墙）把它产品化绕过去了，你的跳板在最关键的用例上没了存在理由。剩下的通用远程和其它 agent，又退回到第二节"自建 DERP 已覆盖"。两头一夹，中间没剩多少。Cursor 的 Web/Mobile agent 也已下场。

来源：Claude Code Remote Control 官方文档 · IT之家报道

四痛点根因被误诊了

"Tailscale 在国内慢"不是 Tailscale 特有的毛病，是任何走海外中继的链路的通病：官方无国内中继、CGNAT 打洞失败时回落海外节点。Zedra（落新加坡/越南）、Happy、ngrok 等同样在打洞失败时回落海外，换工具撞同一堵墙。更关键：你的 agent 流量本来就要出海到 Anthropic（这是大头，省不掉），而控制通道是低带宽文字，海外往返也忍得了。所以"自建国内控制中继"能改善体验，但不构成"非买不可"的护城河。

如果非要做 —— 最靠谱的形态不是产品

主航道 ✅
内容 / 影响力资产。把这篇教程做成精品（你已在做），作为个人品牌 + nocoly 的技术信誉与 lead-gen。零变现压力，复利最高，正好踩中"手机跑 agent"的热度窗口。
更耐放的一篇：横向对比稿 ——「手机驱动 AI agent 的几条路：官方 RC vs Happy vs Moshi vs 自建 DERP vs 跳板，什么时候用哪个」。它的寿命比"单个 hack 教程"长（hack 正在被商品化），骑同一个热词，且正好打你最强的分发能力。
最小试水
"懒人一键打通包"当引流赠品（或 $几 的小工具）：替人把海外中转 + 穿透 + 手机端一次配好。卖的是省事溢价，不是技术空白。要和"折腾一次就免费"的 DIY 人群抢，转化天花板低 —— 只当副线，别当主航道。
不要做 ❌
独立订阅制 SaaS / 托管中继服务。TAM 太薄、护城河被官方 RC 和自建 DERP 两面夹击、付费意愿弱。投入产出不成立。

一句话：真场景，伪商机。需求是真的、热度是真的，但官方 + 一堆免费工具已经把核心需求接住，残余空白薄到撑不起一个产品。把它当你最好的一篇技术内容去打磨，比当一个创业项目去做，回报高得多。

调研维度：① 前置技术核查（自建 DERP）② 品类竞品 + 融资地图 ③ 中国楔子 TAM 与付费意愿 ④ 平台风险。三路独立调研，结论高度收敛。事实核验说明：竞品融资（Conductor $22M、Omnara YC+$500K）、官方 Remote Control 的存在与机制等，均为 2026-06 网络检索结果，未逐一独立复核；TAM 为透明费米估算（非实测）。方向性结论不依赖任何单一数字。
