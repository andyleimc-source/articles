# 我把四份 CLAUDE.md 删掉一半，最贵的浪费不是 token

<img src="image/cover.png">

昨晚看到 Anthropic 的 Thariq 发长文讲 Claude 5 的上下文工程，我把链接丢给 Claude，问：对我的提示词有优化建议吗。

它指出的第一件事，是我自己写的两条规则在打架。

一条说：有多种解读要全部呈现，不清楚就停下来问。往下翻两屏另一条说：回复要短，我要你替我把关，别把过程摊给我看。

这两条每次对话都同时生效。模型得先花力气调和它们，再猜我这次要哪个。

我一直以为文件写太长的代价是费 token。费 token 是小事。

## 他们自己删了八成

文章里有个数字让我坐直了：Anthropic 给 Claude Opus 5 和 Fable 5 用的 Claude Code 系统提示词，**删掉了 80% 以上，编码评测没有可测量的损失**。

原文：https://x.com/trq212/article/2080710971228918066

删了八成还没事，那我的呢。于是我动手改了四份，一个下午：

| 文件 | 前 | 后 | 变化 |
|---|---:|---:|---|
| 全局 CLAUDE.md | 6,465 | 3,762 | 少 42% |
| 产品仓库 A | 6,431 + 12,319 | 5,792 | 每会话少 69% |
| 项目管理知识库 | 19,836 | 9,338 | 少 53% |
| 产品仓库 B | 33,094 | 23,857 | 少 28% |

**内容零丢失。** 全局那份删掉了整整四节通用工程原则，「不要过度抽象」「只改必须改的」这类。每条都是好建议，问题是 Claude 5 已经内置了，我等于把它的系统提示词又背了一遍给它听。

## 最难那份，文件自己写着「别删」

产品仓库 B 那份 33KB，开头有一句：以下全是事故换来的，别删。

这话是对的，所以我一条没删。但我发现，里面每条规则都长成同样的形状：规则，加三百字事故经过。

而那三百字只在有人想推翻这条规则时才需要读。日常干活，你读完它，动作跟没读一模一样。

于是我把事故叙事整段搬进 `docs/why-these-rules.md`，正文只留可执行的规则。砍下 28%，一个字没丢。

这是这轮最大的收获：**gotcha 一律搬家，不许扔。** 踩坑换来的东西一个字都不能少，但「规则」和「事故经过」可以分开住。

## 三个自检问题

模型本来会不会？会，就删。

看仓库能不能看出来？能，就删。

它跟别处的规则打架吗？打，就删一条，别两边都留。

Claude Code 内置的 `/doctor` 也跑一下。它替你做不了的是最后那个判断：这条是真 gotcha，那它该去哪。

方法和四个案例我开源了，MIT：https://github.com/andyleimc-source/context-diet

我们这两年给 AI 写的规矩，都是在补它的短板。短板每三个月变一次，规矩从来不变。你以为在装护栏，其实是给一个已经会走路的人绑沙袋。

> 要删的是噪音，不是知识。而最吵的那点噪音，往往是你自己两年前写下的那条好建议。
