模式一：施工模式

施工模式：便宜 AI 的按卡规范

通过 Task Card 与 AGY.md 强制约束低成本模型
1 自包含的任务卡 (Task Card) 入口
司机模型（或人）将复杂的开发任务拆解为一张高度具体的任务卡，卡片标准是新开会话只读此卡就能独立跑完。卡片需指明：
↳ 开发目标：具体的改动效果与行为逻辑
↳ 指定范围：严格规定仅允许改动的物理文件
↳ 验证步骤：具体的测试用例与构建检查命令
↓
2 隔离施工队铁律 (AGY.md)
施工方（Gemini/agy）被脚本引导至 git worktree 隔离工作区。在开发中必须遵守以下戒律：
✓ 最小改动：严禁修改非指定文件，不允许顺手重构
✓ 遇险停工：拿不准的逻辑不要盲猜，在卡底写明问题并立即退出
✓ 硬性拦截：未通过本地测试与 build 编译的成果绝不允许提交
↓
3 自动环境变量标记
派工脚本在 worktree 中启动施工模型时，在 Shell 中自动注入环境变量：

GIT_AUTHOR_NAME="agy"
所有由施工队产生的 Commit 会自动带上 agy 物理标记，彻底防止人工签名遗漏。
