模式三：返修监督模式

返修监督模式：水位线与分流决策

如何把高级模型的昂贵 token 100% 用在刀刃上
步骤 1 Git 水位线 (Watermark Tag) 锁定增量
在 Git 中维护一个水位线 tag。评审时，脚本只抓取该 tag 之后由 Author: agy 产生的 Commit 变更，历史已评审代码绝不重审。
↓ (增量评审分流)
步骤 2 分流决策树 (Triage & Action)
对于评审中发现的质量问题，根据修复成本由司机（Claude）按规则分流：
微小瑕疵 ↳ 顺手热修
对于拼写、格式或几行以内的小瑕疵，Claude 现场热修并直接提交合并，省去撰写返工单的 token。
大块偏离 ↳ 退回返修
若是架构走样或逻辑错误，在任务卡底部追加返工单 (Rework Card)，将 worktree 倒回派给 agy 重构。
↓
步骤 3 水位线前移 (Forward Baseline)
返修分支重新合并并通过所有自检（Build & Test）后，司机（Claude）执行 tag 升级指令，将 Git 水位线 Tag 前移到 HEAD，完成本次协作闭环。
