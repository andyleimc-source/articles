双 AI 协作机制

两个 AI 一个仓库的协作闭环

施工、驾驶与返修监督三模式的落地实践
模式一：驾驶模式 (Driver Mode) 决策 & 拆图
高能力模型 (Claude) 掌控主干仓库与 CLAUDE.md 顶层规则。负责系统设计、分解子任务，并输出自包含的任务卡 (Task Cards)。
↓ (通过 git worktree 派发任务)
模式二：施工模式 (Builder Mode) 隔离作业
低成本模型 (Gemini) 在物理隔离的 git worktree 独立环境中开发。
约束：AGY.md
严格遵循单一任务卡规范，限制文件修改范围，严禁自主重构。
痕迹：agy 环境变量
自动将 Commit Author 注入为 agy，建立追责机制。
↓ (提交 PR / 代码变更)
模式三：返修监督与增量评审闭环 (Review Loop) 控成本 & 提质量
Git 水位线 (Watermark Tag) 机制 只评审水位线之后的新 Commit，杜绝重复评审
微小瑕疵 ↳ 顺手修复
几行以内的简单修补，由 Claude 顺手修改并直接合并，省去沟通成本。
大块问题 ↳ 追加返工单
架构或逻辑错误，在任务卡底部追加返修说明，退回 agy 重新施工。
